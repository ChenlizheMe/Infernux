# 动画曲线与补间计算

引擎提供 AnimationCurve、Keyframe、WrapMode 和 WeightedMode。曲线用于场景属性、线条、粒子参数和补间采样；不同功能共用同一种曲线资产及序列化格式。

```python
from infernux import AnimationCurve, Keyframe, WeightedMode

curve = AnimationCurve(Keyframe(0, 0), Keyframe(1, 1))
value = curve.evaluate(0.5)
```

## 曲线接口

关键帧通过 `keys`、`get_keys`、`set_keys` 和索引访问。读写返回或接收值副本；关键帧按时间排序。`add_key`、`move_key`、`remove_key`、`clear_keys`、`smooth_tangents` 和 `copy_from` 提供编辑操作。

`get_keys(keys=buffer)` 写入已有的关键帧容器，容器容量应不少于 `length`，多余位置保持原值。
写入的是关键帧值副本，修改容器中的关键帧不会修改曲线。`set_keys(keys=buffer)` 则复制并排序
传入的关键帧；不提供目标容器的 `get_keys()` 直接返回副本列表。

关键帧包含 time、value、in_tangent、out_tangent、in_weight、out_weight 和 weighted_mode。普通段采用 Hermite 插值，加权段采用带权 Bezier 插值并反求时间参数；无穷切线表示阶梯段。空曲线采样返回 0。

阶梯段中，任一相关切线为正无穷时保留左键值，直到真正到达右键时刻；没有正无穷而存在负无穷时，区间内直接取右键值。两种符号同时存在时，正无穷优先。端点使用实际关键帧时间判断，不能用舍入后可能提前变成 1 的归一化时间判断。

普通段在原生快照创建时生成单精度多项式系数，采样复用系数并按固定顺序求值。斜率乘积和求值乘积分别舍入，避免融合乘加改变结果。系数生成使用的时间间隔下限为 0.0001；关键帧时刻及区间端点仍使用原始时间。非常接近的两个关键帧因此可能在到达右端点时发生跳变。加权段使用独立的求根路径，不能用普通段的精度验证替代其审核。

加权段先以单精度计算归一化时间和斜率，再解析求解水平 Bezier 参数。系数绝对值不超过
0.001 时降为二次或一次方程；三实根按固定相位顺序选择区间内的解。三次根保留单精度
对数、双精度指数和最终单精度转换的运算边界，不能直接用 `pow` 或 `cbrt` 替换。
竖直插值使用相同的单精度基函数与累加顺序。权重保留原值，不强行限制在 0～1；非单调
水平控制点仍由同一求解器处理。当前原生数值路径以 Windows 为验收平台。

粒子 GPU 的普通段使用相同计算顺序，并通过 `precise` 保留运算边界。时间间隔倒数在生成常量或上传参数时准备，避免每次采样执行除法。每键仍使用两个 vec4；权重行的最后一个字保存该段倒数，加权段和最后一个键保留为 0。着色器兼容性散列包含曲线辅助代码和参数语义，相关变化会使旧 AOT 二进制失效，需要重新构建。

GPU 加权段使用相同的方程降阶和根选择结构，移除了逐次二分。着色器使用单精度数学函数，
其超越函数精度与 CPU 不同；加权 GPU 数值检查显式给出误差界，普通段继续逐位检查。

`smooth_tangents` 同时更新斜率和相连线段的关键帧权重，权重恢复为 1/3，保留 weighted_mode；端点未连接的一侧和单键曲线保留原数据。斜率与加权计算使用原生单精度运算，并保留乘积与相加之间的舍入，避免不同处理器的融合运算改变结果。编辑会更新 revision，已有的补间和曲线采样会使用新的计算快照。

`constant`、`linear` 和 `ease_in_out` 创建常用曲线。pre_wrap_mode 和 post_wrap_mode 分别控制区间两端的采样方式。曲线可以编辑，不能用作 Python 字典键；`get_hash_code` 提供显式内容哈希，revision 用于失效旧快照。

曲线相等比较包含关键帧的时间、数值、切线、权重、weighted_mode 和循环模式，不包含旧 tangent_mode 元数据。内容哈希包含关键帧元数据，不包含循环模式；空曲线的哈希为 0。原生计算返回固定的有符号 32 位结果，保留浮点数的位模式，包括正负零。revision 未变化时复用结果；首次计算可以复用采样快照，大曲线计算期间释放 GIL。哈希用于内容判断，资产身份仍使用资源标识。

通用曲线没有 16 键限制。粒子可变参数仍受固定 GPU 参数容量约束，超出容量时在边界报告错误；这不限制曲线对象和编辑器本身。

## 计算与资源

补间的时间配方与播放状态分开管理。配方保存时长、延迟和循环配置，可以共享；
每个补间独立保存原生的单循环进度、整数循环次数和延迟进度，不持有 Python 用户对象。
每帧只累加当前循环的单精度进度，累计时间仅作为查询与序列遍历的投影。
这样长期循环不会因为不断增长的单精度总时间而失去帧增量。
时间跳转、重播和回退同步状态，回调和场景对象控制继续由 Python 执行。

Tween 插件同时提供 `CubicBezier` 几何线段工具，也可通过
`TweenCurve.CubicBezier` 访问。`get_point_on_segment` 按参数采样三维点并支持外插；
`get_segment_point_cloud` 按均匀参数生成指定数量的点，默认 10 个、最少 2 个。
传入 `add_to_list` 时会追加点并返回 None。点数与参数步长采用单精度规则，末点不额外吸附。
单点直接进入原生计算；点云先捕获控制点值，再批量执行，大批量数值计算期间释放 GIL。
返回 Python 向量或写入 Python 列表时恢复 GIL。线段工具和运动路径共用多项式求值部分，
各自保留系数计算的舍入顺序。

关键帧数值按 float32 保存，支持无穷值和 NaN；额外的权重标志保留为有符号 32 位数据。
构造曲线或替换整组 `keys` 时，会丢弃时间或数值非有限的键。`add_key` 和 `move_key`
使用单键编辑规则：拒绝 NaN 时间，保留无穷时间和非有限数值；移动失败时原位置的键已被移除。
`copy_from`、深复制和资产读回保留已存储的键，不重新经过整组键的过滤。

严格 JSON 使用 `infinity`、`-infinity` 和 `nan:xxxxxxxx` 保存非有限字段，NaN 编码包含
float32 位模式。线条曲线使用同一种数值编码。编辑器不向绘制接口提交非有限坐标，未编辑的
特殊值保持原样；GPU 数据只编码参与计算的两个权重位，额外标志继续保存在曲线资产中。

关键帧相等比较将 NaN 视为相同数值；不同曲线中的 NaN 字段不相等，曲线自身始终与自身相等。
曲线比较不包含旧 tangent_mode 元数据。原生比较复用不可变快照，大曲线比较期间释放 GIL。
两条曲线的快照均与当前 revision 对应时，比较直接使用这些快照。尚未准备快照或编辑后缓存
已失效时，先比较键数量和循环模式；这些元数据已不同时，不创建新的采样快照。其它首次
比较仍需准备快照，其成本与缓存后的比较不同。

Python 负责编辑和序列化，C++ 持有不可变计算快照，插值数据和旧切线元数据由同一快照保存。曲线变化时重建相关快照；稳定的采样不重复整理关键帧。

关键帧的编辑入口处理数值规范化，读取值副本直接复制已经规范化的字段。原生快照接收曲线整理后的有序数据，不再逐字段复验和排序。单次采样直接进入原生数值接口，支持普通数值和 NumPy 数值标量；不能转换为数值的参数由绑定层报告类型错误。

单键插入和删除使用已有时间索引，不重新排序整条曲线；平滑只复制目标关键帧，并把相邻点交给原生局部计算。未修改的关键帧继续共享内部数据，已交出的关键帧副本、其它曲线和原生采样快照保持原值。只修改切线时，时间索引保持原样。

`evaluate_many` 和 `evaluate_into` 支持批量采样。后者写入已有的连续 float64 缓冲区，可使用标准库 array 或 NumPy 缓冲。调用入口检查布局和重叠关系，内部循环直接计算。大批量计算期间释放 GIL，短调用保留当前锁；释放锁期间不执行 Python 回调和场景修改。

补间系统引用原曲线资产，使用 `(time / duration) * 最后关键帧时间` 映射采样时刻。它不复制曲线，不另设插值器，也不减去第一关键帧时间。

单次采样和批量缓动在原生层使用同一运算顺序，先执行除法并保留双精度结果，再乘曲线末端时间。
不能提前合并成 `time * (最后关键帧时间 / duration)`；极端时长下，这会让中间比例先溢出或下溢，
使本来有限的采样产生错误。零时长及非有限输入使用相同的浮点数规则。无需时长映射的普通批量
曲线仍直接乘时间比例，不增加逐元素除法。大批量缓动同样在原生循环期间释放 GIL。

## 使用与发布

Inspector、原生线条、粒子参数和补间计算共用曲线的数据约定。GPU 参数布局变更需要使旧构建缓存失效。新增原生接口需要匹配的引擎 SDK，不能仅替换 Python 包。

本次更新以 Windows 为验收平台，检查关键帧编辑、权重、阶梯、循环边界、批量缓冲、序列化、
渲染消费者和插件运行。独立 Release Player 检查曲线驱动的补间、场景组件加载、暂停、刚体运动
和实际 UI 绘制。大批量加权采样另行检查释放 GIL，完整 Player 验收不能由数值内核测试代替。

内部采样材料、来源记录和过程报告不进入公开仓库或发布包。

## 补间标量精度

补间的普通 Python 浮点终点使用双精度；显式 `numpy.float32` 终点使用单精度，
setter 收到的值保持为 `numpy.float32`。单精度标量的循环累加、插值与吸附由
原生计算快照完成，保留表达式与赋值之间的舍入位置，不复用向量运算的中间舍入。

快照和类型选择发生在初始化或配置修改时。稳定播放复用已绑定的采样器，
单精度批量任务直接写 float32 缓冲区，大批量计算期间释放 GIL。
这项功能需要同时更新对应的原生 SDK。

显式标量支持 NumPy 的 float32、float64、int32、int64、uint32、uint64。
数值与缓动的调用入口在配置时绑定，正常采样和自定义缓动都保留声明的类型。
批量计算直接写入对应类型的缓冲区，入口处理缓冲布局，内部循环不逐元素验证。

无符号 64 位计算使用固定大小的原生整数暂存区完成十进制运算，不依赖 Python
十进制对象或其它数值库。数值溢出遵守补间的容错设置与定位、逐帧更新规则；
其余目标和回调的生命周期处理保持在补间调度层。
