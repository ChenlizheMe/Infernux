# 铰链位置电机

`HingeJoint` 可以通过原生物理约束驱动动态刚体。设置 `motor_enabled=True` 后，Jolt 在固定物理步内施加受限扭矩，追踪 `motor_target_angle`；不会直接改写 Transform。

| 属性 | 单位与含义 |
| --- | --- |
| `motor_target_angle` | 度，相对本次约束绑定的零姿态；正方向为 owner 相对 connected body 绕轴的右手旋转 |
| `motor_stiffness` | N m/rad，非负的位置增益 Kp |
| `motor_damping` | N m s/rad，非负的电机速度增益 Kd，属于电机扭矩限幅内 |
| `motor_max_torque` | N m，有限、非负的对称扭矩上限；0 表示无电机扭矩 |
| `joint_damping` | N m s/rad，被动关节粘性阻尼，电机关闭时也存在，不受电机限幅约束 |
| `friction_torque` | N m，与载荷无关的关节干摩擦上限，包含静摩擦区，不是接触摩擦系数 |
| `armature` | kg m²，折算到关节轴的电机转子惯量；非负，0 表示无附加惯量 |
| `current_angle` | 度，相对绑定零姿态的实际物理角度 |
| `current_angular_velocity` | 度/秒，owner 减 connected body 的实际角速度在当前铰链轴上的投影 |

目标角度保留用户填写的值。启用限位时，求解器使用限位内的目标；修改限位会重新夹取目标，而不会重新定义关节零姿态。启停电机、修改驱动参数不会重建约束。关闭电机允许自由运动，已有角速度仍受物理约束、阻力和接触影响，不会强制归零。

电机直接使用 SI 单位的 Kp/Kd，不再通过频率和阻尼比换算。刚度与电机阻尼同时为零时不产生电机扭矩，不能退化为硬约束。电机、被动粘性阻尼和干摩擦在同一铰链轴上解析合并求解，只有电机部分受到 `motor_max_torque` 限幅。它们仍与锚点、限位和接触约束共同迭代；实际响应取决于质量惯量、步长与全系统收敛情况。

单步离散采用隐式位置弹簧：电机扭矩对应 `clamp(-Kp*(angle-target+h*angular_velocity)-Kd*angular_velocity, ±max_torque)`；被动力矩为 `-joint_damping*angular_velocity`，滑动干摩擦反向限幅，静止时可在摩擦范围内平衡剩余力矩。不能把这里的隐式数值耗散当作真实电机阻尼。`armature` 不增大刚体自身的惯量张量，而以关节轴的转子速度和冲量参与 Jolt 原生速度迭代；电机、被动损耗与附加惯量在该轴上联合更新。几何约束、接触和限位保留 Jolt 自带的求解与并行调度，不组装全链稠密矩阵，也不切换到另一套物理岛求解器。渲染或神经执行器不承担物理积分。

电机参数参与场景保存、克隆与 Inspector。运行时缩放保留关节坐标、零姿态与电机目标/状态。禁用整个组件、断开或更换刚体、修改 anchor/axis 会按原有语义释放并重新绑定约束，新绑定姿态重新定义零角度；电机配置保留并重新应用。未绑定的关节角度和角速度均为零。

转子速度属于物理状态：episode 批量重置和显式休眠会同步重置；缩放重建保留原转子状态；普通限位/增益修改只清求解猜值。完整原生 SaveState/RestoreState 保存转子速度。刚体的陀螺力矩使用原 Jolt 积分路径。

跨关节和接触的精度仍取决于原生迭代收敛；有限轮数后的转子速度与刚体相对角速度可能存在残差，不能直接覆盖历史来隐藏它。位置修正使用原生 Jolt 路径，不写转子速度或速度阶段的冲量缓存。当前接口不是保证零关节误差的降维 articulation；实物参数标定、多关节受力精度以及 CCD、恢复系数等工况需要各自的实际证据，不能由静止或休眠结果推定。

重复写入相同的电机配置和有效目标不会唤醒刚体；启用中的目标变化、启停或物理系数变化仍会唤醒。电机关停时可以预先设置目标，等启用后使用。刚体组件退出或碰撞体离场提交时，由物理生命周期退休关联约束；场景事务的临时暂停保留原约束，回滚不重定义零姿态。Hinge/Slider 仅对尚未绑定的组件重试创建，两端必须参与物理场景，已排队加入的 actor 在本轮提交后参与积分；已绑定组件不在每个固定步重复解析两端刚体。

机器人动作应在固定控制相位写入，随后推进物理，再采集状态。渲染帧、控制步和物理子步应分别计数。此接口是单关节控制能力；大量关节的训练仍应使用批量观测和动作传递，避免 Python 逐关节热点调用。

## 批量观测与动作

`infernux.physics.HingeJointBatch(joints)` 在 Play 中绑定一组已经创建物理约束的关节，保存顺序和严格组件身份。构建时要求非空、无重复、同一 Scene。它借用关节，不拥有组件；销毁、禁用、重新绑定关节或进入另一 Play 会话后需要重新创建绑定。运行时缩放保留约束零位和外部约束身份，因此原批次仍可使用。

`batch.read_state(out=None)` 返回 `motion` 和 `physics_step`。`motion` 是 float32 `[N,2]`，依次为实际角度（弧度）和角速度（弧度/秒）；与单组件 Inspector 的度制区别开。`out` 可以是可写、连续的 CPU float32 NumPy 数组，或 CPU `inx.buffer`，容量可大于 N，尾部不改动。

`batch.set_motor_targets(targets, expected_physics_step=...)` 接收 CPU float32 `[N]` 或 `[N,1]` 的弧度目标。它先校验全部关节身份、可选步号和全部目标的有限性，再应用到现有位置电机，不自动启用电机，也不推进物理。可直接传入神经图 CPU 结果的 `as_buffer()`，不需要逐行转换或 Python setter 循环。

`physics_step` 对应 `SceneManager.completed_fixed_step_index`：物理积分正常返回后、接触事件回调前更新，空世界的固定步也计数。原 `fixed_step_index` 表示已经开始的固定步，二者在 FixedUpdate 中不同。把采样返回的完成步号传给写入口，可拒绝跨过下一次物理积分的旧动作；它不代替应用自己的 episode/reset 管理。所有批量读写限制在物理 owner 线程。

在 program 外创建 `source = nn.Channel.hinges(batch)`，将其作为 `nn.program` 的参数；在正文中对该参数调用 `get_vector2("motion")`。prepare 只获取字段布局；提交后，在原共同预算内采样到请求私有 CPU 存储，再由原 Transfer/Plan 执行。CPU 模型直接引用此快照；GPU 模型沿原传输管线上传，重复字段共享一次采样和载荷。请求的 `metrics["source_physics_step"]` 记录此次采样返回的步号。动作需要 CPU 回读时指定 `result_device="cpu"`，再调用批量写入口；不会隐式下载 GPU 缓冲。

暂停固定物理推进、等待一次受管推理完成、应用动作后再推进控制步，是训练环境可以采用的明确时钟安排。渲染和神经计算仍可在等待期间继续。完整机器人/训练示例维护在桌面 NNNP1 项目，不随引擎源码附带。
