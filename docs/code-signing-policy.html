Code signing policy

This policy covers official Infernux release artifacts published from the ChenlizheMe/Infernux repository. It does not cover community plugins, downstream builds, or games exported by engine users.

Free code signing provided by SignPath.io, certificate by SignPath Foundation.

01

Team roles

  • Committers and reviewers: Lizhe Chen (@ChenlizheMe)
  • Approvers: Lizhe Chen (@ChenlizheMe)

Changes from people without commit access require maintainer review. Every release signing request requires a separate manual approval in SignPath.

02

What may be signed

Only official Infernux executables and installers built from this repository by the linked, origin-verifiable GitHub Actions build may receive the release signature. Build definitions are versioned with the source. Signed files identify the product as Infernux and use one consistent product version throughout a build.

Upstream open-source binaries may be included in a package, but are not re-signed as Infernux software. Test signatures are not published as trusted release signatures.

03

Network and privacy disclosure

The engine and editor do not upload project files, scenes, scripts, assets, or gameplay content to Infernux services by default.

Automatic update checks are enabled by default and can be disabled in Hub settings. Existing disabled preferences are preserved. The installed InfernuxHub requests the public Hub update catalog and release notices from infernux-engine.com at startup when checks are enabled. A manual update check requests the catalog. If the catalog cannot be reached, Hub may request the same document from raw.githubusercontent.com. Installing a Hub update requires confirmation. The Hub requests public release metadata from PyPI and GitHub when the user opens the engine installation workflow. Those services receive ordinary HTTPS request metadata, such as the client's IP address, user agent, and requested URL; no project content is included. See the GitHub Privacy Statement and PyPI privacy notice.

Engine, build-support, and plugin downloads follow a user-selected install or update. Online documentation, network-capable plugins, MCP connections, exported games, and third-party software operate under their own configuration and privacy policies.

04

Installation and removal

Installing InfernuxHub is an explicit user action. It creates application files and a per-user uninstall entry; managed engines and build support are created only when the user installs them. On Windows, remove InfernuxHub through Settings > Apps > Installed apps. On Windows or Linux, the Hub can also be started with --uninstall. Projects and shared project records are preserved.

信任 · 发布 · 隐私

代码签名策略（Code signing policy）

本策略覆盖从 ChenlizheMe/Infernux 仓库发布的 Infernux 官方制品，不覆盖社区插件、下游构建或用户使用引擎导出的游戏。

Free code signing provided by SignPath.io, certificate by SignPath Foundation.

01

团队职责

  • 提交者及审核者（Committers and reviewers）：Lizhe Chen（@ChenlizheMe）
  • 签名批准者（Approvers）：Lizhe Chen（@ChenlizheMe）

没有提交权限的人所提交的改动，必须由维护者审核后才能合并。每一个发布签名请求都需要在 SignPath 中单独进行人工批准。

02

可以签名的内容

只有由已关联、可验证来源的 GitHub Actions 流程从本仓库构建的 Infernux 官方可执行文件和安装器，才可以获得发布签名。构建定义与源码一同接受版本控制。签名文件必须将产品标识为 Infernux，并在一次构建中使用一致的产品版本。

软件包可以携带上游开源二进制文件，但不会将其重新签名成 Infernux 软件。测试签名不会作为受信任的发布签名分发。

03

联网与隐私说明

引擎和编辑器默认不会向 Infernux 服务上传项目文件、场景、脚本、资产或玩法内容。

自动检查更新默认开启，可在 Hub 设置中关闭；用户已有的关闭选择会被保留。启用检查时，安装版 InfernuxHub 会在启动时向 infernux-engine.com 请求公开的 Hub 更新目录与发布通知；手动检查更新会请求更新目录。若目录无法访问，Hub 可以从 raw.githubusercontent.com 请求同一份文档。安装 Hub 更新前仍需用户确认。用户打开引擎安装流程时，Hub 还会向 PyPI 和 GitHub 请求公开的 Release 元数据。这些服务会收到普通 HTTPS 请求元数据，例如客户端 IP 地址、User-Agent 和所请求的网址，但不包含项目内容。详见 GitHub 隐私声明与 PyPI 隐私声明。

引擎、构建支持和插件只会在用户选择对应安装或更新操作后下载。在线文档、能够联网的插件、MCP 连接、导出的游戏及第三方软件遵循各自的配置和隐私策略。

04

安装与卸载

安装 InfernuxHub 是用户显式发起的操作。它会创建应用文件和当前用户的卸载入口；托管引擎与构建支持只在用户选择安装时创建。Windows 用户可以从设置 > 应用 > 已安装的应用卸载；Windows 和 Linux 也可以使用 --uninstall 启动 Hub。项目和共享项目记录会被保留。
