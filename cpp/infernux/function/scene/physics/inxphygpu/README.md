# inxphygpu

The native inxphygpu Slang modules follow MuJoCo Warp's shared model and world-indexed data. `InxPhyGpuStep` runs the compute pipeline, and `InxPhyGpuSceneRuntime` connects it to scene authoring and result publication. The reference revision is MuJoCo Warp 4.0.1, `2db59f4d929dab714d85fab946d93427d2aa56e7`. [Upstream source](https://github.com/google-deepmind/mujoco_warp/tree/2db59f4d929dab714d85fab946d93427d2aa56e7) · [Apache 2.0 license](../../../../../../licenses/mujoco_warp/LICENSE)

On Vulkan, a fixed step can replay the recorded compute commands for each numerical substep. Replay requires the same pipelines, bindings and dispatch parameters. Indirect dispatch counts continue to come from device buffers. Uploads, contact collection and result publication are recorded for the current step.

Scene participants run Predict before collision, Prepare and Exchange after collision, and Accept after integration. An Exchange with rigid targets gathers their current device motion, runs the project recipe and applies its impulse before the constraint solve. The project sees one coupling iteration per substep. The contact solver manages its own numerical iterations. If a fixed step with project work exceeds solver capacity, its rigid motion is restored and the publication flags the project state as invalidated. The scene must restart before it advances again.

A replacement scene layout can initialize from its last accepted device publication. It matches worlds by ID and simulation epoch, then matches surviving bodies by ID and actor generation. A compute pass imports the matching body poses, velocities and fixed clocks in the initialization packet. New worlds and bodies use the authored seeds. The previous publication remains available to existing consumers, and the new layout builds its own contact and solver scratch.

Scene rigidbody motion settings are shared across a compiled batch. Linear and angular damping and speed limits act on the free velocity before contact and joint solving. The same change updates the smooth generalized force and acceleration used by the solver. Immediate velocity commands apply the limits in command order. Pose integration advances the center of mass and converts the result back to the published body origin.

Scene rigidbodies in Continuous or ContinuousDynamic mode run a linear sweep after velocity and pose integration. The sweep uses the discrete collision filters and the same convex and triangle-mesh geometry as the scene shape queries. A workgroup resolves point impulses per world over the admitted collision substep and publishes the corrected positions and velocities before sleep and clock advance. For a commanded kinematic body, the sweep uses its prescribed translation and the end orientation. Impact capacity grows with the number of CCD sources in the world. Capacity exhaustion and unresolved sweeps report a fixed-step error and retain the previously accepted state and clock.

The fixed-step contact stream combines swept impacts and discrete manifolds by collision substep. Scene solid contacts within the configured speculative contact distance retain their measured separation for callbacks. Positive separation samples carry contact observations only. Trigger events follow geometric overlap.

Kinematic targets carry the requested duration and optional Transform drive speed limit. Commands compose position and rotation in author order. The solver derives the prescribed center-of-mass velocity from that duration, uses it across the fixed tick's collision substeps, and samples the resulting pose at the fixed boundary. A subsequent tick without a move holds the accepted pose.

A live topology refresh takes the last accepted publication for the same world, simulation epoch and fixed step. Joint identities retain their bound frames and automatic rest lengths across row changes. Changed body scale applies to the retained local anchors, and an explicit joint rebind captures a new reference. The device state transfer retains the same accepted fixed step.

The mass solve produces the smooth acceleration. The CG and Newton solvers supply the acceleration used for integration in supported rigid-contact cases. The port accepts applied generalized forces and generates joint, tendon, site and contact adhesion actuator forces from resident control. The implicit and discrete paths cover dry rigid dynamics, including joint, tendon and actuator metric terms. Other narrowphase pairs and constraint producers and full per-island solver compaction require their corresponding stages.

The model contains the topology and inertial data shared by all worlds. `model.slang` defines records using 16-byte fields. Scalar generalized coordinates and the mass matrix remain tightly packed. Dispatch X addresses branches, bodies, joints or degrees of freedom, and dispatch Y addresses worlds. Dynamics arrays use a separate contiguous row per world. Quaternion order is `wxyz`. Matrix records store three padded rows.

`BuildInxPhyGpuModel` compiles a native body forest and geometry attachments to those storage records. It creates device row zero for the world, puts each subtree in depth-first order, and keeps a source-to-device body map. It also compiles the shared symmetric mass adjacency and the compact, small dense, tiled and sparse mass factor tables. Initial generalized positions and kinematic poses are returned separately for seeding per-world state. The scene backend must supply the remaining collision shape, material, constraint, and control inputs.

`branches` packs the `nbranch + 1` offsets first, followed by MuJoCo Warp's branch body indices. Each leaf branch evaluates its parent chain locally. The first branch containing a body owns the output stores for that body and its joints. Seed world body zero with the identity pose before dispatching. Inertia entries consume contiguous subtree ranges, and the mass rows consume the parent DOF chain and CSR row metadata from the same model. `DofModel.armature` holds the generalized diagonal armature for the row. The first bit of `DofModel.flags` sends gravity compensation through actuation.

Run the position, inertia, and bias entries in table order. The bias entries use one gravity vector per world. Factor the mass blocks after assembling the mass matrix, and solve each block after both its factor and the generalized force are available. Euler advances velocity before position and time. Resource dependencies between those dispatches require compute barriers.

A body wrench gives world-space torque and force at the body's inertial origin. When body wrenches or body gravity compensation are present, center the wrenches at their tree centers of mass and project after the passive stages and before actuator force projection. The body projection publishes applied force and gravity compensation separately, adds the passive share to the passive force buffer, and adds the Cartesian applied force to a separate output of the requested generalized applied force. Supply the effective per-world gravity to both bias and gravity compensation, including zero under disabled gravity. Assemble the generalized force after passive and actuation. With implicit Euler damping, assemble the effective mass and solve with the resolved generalized force as the right-hand side. `advance_velocity` integrates the effective acceleration and stores the resolved, undamped acceleration for warm-starting. Bind the same acceleration to both slots for the explicit damping case.

With material adhesion enabled, run `add_contact_adhesion` after narrowphase and the initial passive force writers, before smooth force assembly. Bind the same contact settings and topology as contact row construction. Each eligible contact contributes the material's attractive force along its normal, with opposite signs on the two bodies. This includes physical records in the gap. The contact rows retain their matching adhesive reference acceleration shift. The pass uses the same normal projection as body adhesion transmission and adds to the existing passive force.

## Actuation

The shared actuator model has one record per actuator. Its first field supplies the transmission target, first control and activation offsets or `NoIndex`, and flags. Its mode field selects dynamics, gain, bias and transmission. Free and ball transmission support gears in the joint or parent frame. Ball and purely rotational reference-site position setpoints wrap around the nearest equivalent angle, including for stateful drives.

Bind per-world timestep, generalized state, control, activation slots and any tendon state. The dimensions records are `(actuators, controls, activation slots, site and body moment columns)`, `(site actuators, tendons, tendon Jacobian columns, body actuators)`, and a third record with the per-world contact capacity in its first word. The force stage writes length, velocity and force for each actuator and the derivative of each activation slot. The activation buffer stores a value and derivative per slot. Cook one extra dynamics record only for each muscle or DC motor. A DC motor's control mask uses position, velocity, feedforward and voltage bits in order. The state mask places slew, integral, temperature, bristle and current states in that order, using only enabled slots. Muscle gains use the authored length range and reference acceleration, and activation uses separate rise and fall constants and the authored smoothing width.

For each site actuator, cook its driven and optional reference site body-local poses and a sparse row in increasing DOF order. With a reference site, this row contains only DOFs exclusive to one of the two ancestor chains. Store a flag on columns from the reference chain. A site without a reference uses the driven site's entire chain and applies a wrench in that site's frame. After body poses, tree centers of mass and centered DOFs are ready, `evaluate_site_transmission` fills the site moment columns and the actuator's length and speed in `actuatorStep`. Run this stage only for models with site actuators.

Cook a dense DOF row in the shared moment buffer for each contact adhesion actuator. Its record names the actuator, the row start and the driven body. Include the subtree body count in the fourth word of each body record in the contact topology. After narrowphase emits this step's contacts, run one workgroup per body actuator and world before force evaluation. The workgroup averages the negative relative normal Jacobian of the driven body's contacts, including records in the contact gap. Sensor-only records carry no physical force. The body transmission has zero length and its velocity is the moment row times generalized velocity. It writes zero moments when the body has no contacts.

The shared DOF table points into an adjacency array of `(actuator, moment index)` pairs. Joint transmissions use the joint-relative DOF. Tendon, site and body transmissions use an absolute column within their Jacobian or moment storage. When tendon transmissions exist, apply `limit_tendon_actuator_forces` before force projection. Each tendon applies the aggregate force range before the individual ranges. DC motor cogging and LuGre friction are added after those limits. Each projection thread then gathers all contributions to one DOF in model order, adds the actuator's share of gravity compensation and applies its generalized force limit. Use that output in `assemble_smooth_force`.

At Euler advancement, update activation values once using the stored derivatives and timestep. Early activation can use the predicted value in force evaluation. Current and LuGre bristle states use exact updates at the sampled transmission speed. The other motor slots use Euler advancement with integral clamping. Activation values are committed at the fixed-step advancement boundary.

## Implicit-fast fixed step

Run the same forward dynamics and constraint solve. Use `evaluate_implicit_actuators` when the step needs actuator derivatives. It evaluates velocity derivatives alongside the force and writes them to the W lanes of the two moment records. Finalize them after the force limits and projection are available. Each packed mass slot uses a range of contributions containing an actuator ID and the two moment source indices. The sources use the same indexing as force projection. These contributions supply the actuator term in the symmetric effective matrix `M − dt ∂f/∂v`.

Use `assemble_euler_mass` to initialize the effective matrix and add the diagonal joint damping derivative. Add tendon damping with the same sparse Jacobian lists as tendon armature. The links must cover the union of damped tendons and tendons with armature. Cook damping from both the joint or tendon and the attached actuators' gear-scaled contributions. The step recipe selects the assembly passes and coefficients according to the model's enabled forces.

Multiply the original packed mass by the resolved acceleration using the shared symmetric adjacency. Factor and solve the effective matrix with that product as the right-hand side. An independent free tree has exactly six DOFs, including any welded descendants. Cook its root body and first DOF once. Restore these packed blocks from the original mass before the symmetric factorization, then overwrite their solved accelerations with the local pivoted six-by-six solve. That solve uses the original mass, its own diagonal damping term, and the nonsymmetric gyro derivative. Store the resolved acceleration for warm start and integrate the effective acceleration. Advance activation, position and time once per fixed step. The recipe can reuse its device allocations and execute without intermediate readback.

## Full implicit fixed step

Use the same right-hand side and smooth velocity derivatives as implicit-fast. Run `differentiate_rne` after the velocity phase. Each input DOF differentiates bias acceleration and force through its owning body's subtree in parent-first order, then accumulates force derivatives back to the root of that subtree. Pack one pair of spatial vectors for each affected body and input DOF. Store them by input DOF and body order, with a separate range per world. Reuse this scratch across fixed steps.

Cook the full symmetric sparsity pattern for the nonsymmetric values. Entry columns are sorted and each has the address of its transpose. The packed smooth-mass index is optional for entries outside the original mass pattern. For each entry, map its bias derivative to the output DOF's owner within the input DOF's subtree. If the output DOF is on an ancestor of the input DOF, use the input's subtree root. Unrelated bodies have no bias derivative. Use `NoIndex` for absent mappings. The shared topology header stores the full entry count, derivative record count and the row and entry table starts. Each row stores the first, diagonal and end matrix indices and the derivative range start for that DOF.

`assemble_implicit_matrix` adds the timestep-scaled projected bias derivative to the mapped smooth effective mass. Dispatch X covers DOFs and Y covers worlds in both assembly stages. Run `factor_solve_implicit` with X covering worlds in groups of 32 and Y set to one. It performs reverse sparse LU and both triangular solves in place. The integration recipe then runs the independent six-DOF free-tree solve on its original packed mass, overwrites those acceleration entries, and advances the fixed step. The raw forward acceleration remains the warm start.

## Discrete fixed step

After the velocity phase, `evaluate_discrete_joint_terms` evaluates the tangent stiffness and damping of each joint at the current pose and velocity. It writes two scalars per DOF and world, the diagonal metric correction `h D + h² K` and the force shift `−h K v`. Use the authored spring reference and the combined DOF damping. The joint metric covers free, ball, slide and hinge joints. Bind zero coefficients for disabled springs or dampers. `assemble_discrete_joint_metric` adds those terms to the original mass and smooth force, keeping the original packed sparsity pattern.

With tendon or actuator metric terms, preserve those original slots in a shared packed matrix and append the unique pairs reached by the transmission Jacobians. The layout record starts with the original and extended packed counts. Initialize the extended matrix from the joint metric. Cook one contribution range per packed slot for each kind of transmission. Each link identifies a transmission and its two Jacobian source indices. The per-DOF shift uses the existing transmission lists. For actuators, run `evaluate_discrete_actuators` with normal force evaluation, then `finish_discrete_actuator_terms` after the tendon and joint force limits and projection. It uses length and velocity derivatives, clamps the restoring slopes, and computes the coefficient and force shift for each transmission. The rank-one passes add the outer products and project the shifts through the same Jacobians.

The full effective matrix feeds the smooth solve and every CG or Newton mass product. Cook the effective symmetric adjacency for those products. The direct smooth solve also needs the symbolic fill of the effective pattern in the existing reverse LU row format. Each symbolic entry points to the packed value or uses `NoIndex` for a zero-fill entry. Scatter and factor this matrix in device scratch, which is reusable across fixed steps. The original packed diagonal slot indices stay valid for constraint regularization, using the effective stride for the larger matrix.

Set `DiscreteConstraints` in the shared row settings so contacts, equalities, limits and friction loss use the discrete reference acceleration and regularization. Clear per-DOF coupling flags before projecting the tendon and actuator shifts, or before regularization when there are no transmission terms. After all rows are emitted, run `regularize_discrete_constraints` before building the initial residual. It scales each contact block by the ratio of effective to original inverse weight along its first Jacobian row. Other rows use their own Jacobian. The same pass marks every generalized coordinate with a nonzero constraint coefficient. Run `solve_discrete_free_bodies` after the constraint solve and before integration. The local six-DOF correction uses the joint-only metric block and the shifted force for an independent tree with neither a transmission nor a constraint on its DOFs. The final acceleration is both integrated and retained for the following warm start.

## Runge–Kutta fixed step

Record four instances of the existing forward dynamics sequence in the same work recipe. Run `advance_rk4_activation` after each solve if the model has activation state, then `advance_rk4_stage`. The settings record carries the stage index (0 through 3) and flags to restore initial actuation length and velocity for wrapped actuation and DC motors. Control and world timestep are frozen for the fixed step. Dispatch X covers actuators or joints in groups of 64 and dispatch Y covers worlds. Dispatch at least one joint group for an empty world so its clock advances.

Allocate per world `nq` initial position scalars and `nv` records of four floats, holding the initial velocity, corrected stage velocity and weighted velocity and acceleration. Actuators retain two floats per activation for the initial value and weighted derivative, and two floats per actuator for initial length and speed. Reuse the allocations. Intermediate stages update trial states from the initial position, velocity and activation. Ball and free-joint angular velocities use the exponential-map derivative before weighting. The final stage publishes the weighted acceleration, retains the fourth solve for warm starting and advances world time by one fixed timestep. Trial state is private to the fixed-step recipe.

## Tendons

Prepare the segment, column and sparse influence lists once per model. The dimensions buffer contains `(tendon count, input segment count, Jacobian column count, resolved segment count)`, `(nq, nv, body count, packed mass length)` and a third record with the wrap geometry count in its first word. A tendon model names its resolved segment and column ranges, polynomial stiffness and damping, spring length range, total armature and reference length. Cook actuator inertia and damping contributions into the tendon coefficients using the authored gear. The zero-segment form stores fixed joint coordinates and coefficients directly in the column table.

Each spatial segment stores two body-local attachments, an inverse pulley divisor, a resolved output slot and an optional wrap geometry index. Each wrap descriptor names the geometry body and tree root, the sphere or cylinder flag, a local pose and radius, and an optional body-local side site. A direct segment uses one output slot. A wrapping segment reserves two slots for the tangents and stores its surface arc length with the first slot. When the route clears the geometry, the first slot describes the direct line and the second carries zero contribution. The wrap output records both world-space contact points and the unscaled arc length for each geometry and world.

Cook a sparse influence only when a potential variable endpoint's chain contains the DOF. The low two bits hold the endpoint mask for a clear route, the next two hold the mask for an active wrap, and bit 4 enables the armature derivative. Mask both endpoints out when they belong to the same body. The reference model compiler disallows armature on tendons with wrap geometry. The derivative accumulates direct spans preceding the first wrap descriptor, following the upstream runtime. The column supplies the quaternion DOF owner for derivative evaluation.

Evaluate spatial segments after position kinematics and the body velocity phase. Assemble one workgroup per tendon and world. The same sparse Jacobian supplies tendon speed, passive forces, matrix contributions, actuator moments and constraint rows. Project passive force and the armature-dependent bias into the existing force buffers. Add the tendon armature using the cooked adjacency for the existing packed mass matrix. Generalized force and mass projection each give one thread ownership of an output element. Initialize the joint passive forces and base rigid-body bias and mass before adding the tendon contributions. Factor the augmented mass before solving.

`emit_tendon_constraint_rows` consumes the resident lengths, velocities and Jacobian. Coupled equality merges the two sorted supports, including shared coordinates. Length limits and friction use the same unilateral and force-capped objectives as joint limits and DOF friction. Submit all active constraint producers before the shared solver reads the row counters.

## Mass layout

Classify each kinematic tree once when building the shared model, following upstream `m_block_layout`. Compact diagonal and full triangular blocks through six DOFs use the scalar entries. Other blocks through 64 DOFs use a workgroup tile, with the upper triangle gathered from CSR using `tileElements`. Absent entries carry `NoIndex`. Larger trees use the sparse entries. Each tiled or sparse workgroup owns a tree in one world. The sparse workgroup gathers contributions into a single writer per row and advances through tree levels on-device.

Factor rows store packed dense block allocations followed by an optional CSR-shaped sparse region. Compact and sparse blocks store reciprocal diagonals in the per-DOF scratch array. The shared `sparseTopology` buffer starts with a four-word header containing the offsets of the level, row and contribution sections. Four-word block records follow. Within each block, the levels list DOFs shallowest first. A row's contribution records list each descendant DOF and the CSR entry for the pair. Submit an entry only when its block list is populated.

## Broadphase

Project bounds after geometry kinematics. The merge and inclusive scan entries use alternating buffers and strides of 1, 2, 4, and so on for the shared geometry count. The sweep workers take their work count from the final prefix sum for their world. The pair rule table has one row per geometry, one sentinel, and one row per authored override. The shader evaluates masks, welded owners, dynamic participation and optional parent filtering, then looks for a pair-specific override. Explicit material pairs bypass those default filters. Sensors can retain detection for an excluded physical pair. Dispatches for an empty geometry set are omitted.

Set the batch candidate capacity through `sweepSettings`. The emission stage appends candidate records to a shared stream. Each record holds two geometry IDs, an explicit pair ID, a sensor ID, and the originating world. The global counter retains the total requested count, including requests beyond the allocation. Reject an overflowed step at its completion boundary. Sleep filtering and per-world missing meshes require the matching model and state columns.

## Primitive contacts

Run `prepare_narrowphase` once after candidate emission, with one invocation per world on Y. It clears each world's contact counter and writes two 16-byte records to an indirect buffer. The first covers the stored candidates in groups of 64. The second covers the smaller of that count and the convex workspace capacity in groups of 32. Bind the first record for `collide_primitives` and the second for `collide_convex` and `collide_heightfield`. A batch with zero candidates produces zero groups. Declare compute-write to indirect-read dependencies on this buffer in the reusable recipe. Candidate and contact counts require no host readback between these stages.

The material table stores geometry rows first, then explicit pair overrides. Geometry rows supply sliding, torsional and rolling friction. Explicit pairs supply the five contact coefficients. Contacts carry signed distance, frame, material, feature ordinal, and constraint and sensor flags. Oriented box pairs test separating axes and clip the incident face or construct an edge witness pair. Face contacts preserve polygon order and carry up to eight points. Contact counts remain per world and retain any overflow.

The contact settings buffer has two `uint4` records. The first supplies the geometry count, batch candidate capacity, contact capacity per world, and batch convex workspace capacity. The first word of the second record holds the narrowphase flags. Set `UseConvexBoxes` to select the native convex route, as MuJoCo Warp does by default. Clearing it selects the authored primitive SAT mode for box pairs. Set `UseConvexMulticontact` to enable face and edge manifolds for the additional supported convex pairs. Plane-cylinder cap contacts use an in-plane radius direction when the cap is parallel to the plane, including rotated planes.

## Convex distance

`collision_geometry.slang` shares the collision shape layout and frame transforms with primitive narrowphase. `convex_support.slang` evaluates sphere, capsule, ellipsoid, cylinder, box and mesh-hull supports. Mesh geometry references its local hull vertices and optional adjacency table in the immutable convex model buffer. The adjacency representation uses MuJoCo Warp's packed offsets and vertex IDs. The support cache tracks the last hull vertex for the life of the query.

`convex_distance.slang` uses the signed-volume simplex reduction, duality gap and support-plane cutoff from MuJoCo Warp's GJK. The query runs in a frame translated to the first geometry's center. For shallow contacts the convex phase inflates the reduced-geometry witnesses by the radii and contact margins. For overlaps it retains the support pairs and vertex IDs needed by EPA. Close-to-collinear triangles compute normalized barycentric coordinates from a common origin to limit FP32 cancellation.

`convex_penetration.slang` expands an EPA polytope seeded by a GJK segment, triangle or tetrahedron. The vertex range stores two `uint4` records per support pair, with float coordinates bit-cast in XYZ and the signed feature ID in W. The face range stores one `uint4` per face, with the projected point in XYZ and three 10-bit vertex indices plus face flags in W. The horizon uses a separate `uint` range. The returned face stays available until that worker takes its next pair. EPA reports seed boundary, capacity exhaustion, degenerate expansion and iteration limit separately. A capped expansion retains its best face and witnesses.

`convex_features.slang` uses the support vertex IDs on the final EPA face to restore the incident features. `convex_manifold.slang` clips those features, matches the opposing witnesses and reduces the intersection to at most four contact points. `convex_contacts.slang` appends them to the same per-world contact stream used by primitive narrowphase. Plane-hull pairs use the supporting hull vertex and its incident polygon.

With heightfields present, run `collide_heightfield` after the convex pass and before the contact consumers. It uses the same resource bindings and device contact counters. The immutable convex model header then includes record 3 with the heightfield record offset, packed sample offset and per-pair candidate capacity. A field uses two records with its row count, column count, first sample and physical size. Its collision shape names the field in the second type word. Size is `(half width, half length, height scale, depth below the field)`. Pack four normalized height samples into each record in model row order.

The heightfield pass scans the convex shape's support subgrid in field-local space. It visits the two triangular prisms per cell, applies the heightfield witness correction, and selects up to four contacts from the resulting candidates. It stores candidate positions and normals in the convex worker scratch used for temporary polygons by the preceding pass. Allocate the larger of the polygon workspace and two records per heightfield candidate for each worker. Status bit 6 reports a heightfield that exhausted its candidate capacity before traversal finished. Triangle surface collision remains a separate stage.

Windows Vulkan single-step comparisons cover sphere, capsule, ellipsoid, cylinder, box and mesh hull against a rotated heightfield at one and eight worlds. Sphere and capsule contacts at prism boundaries still differ in wider batches. Verify contact selection and multi-step trajectories before routing production heightfields to this pass.

The prism trace isolates one mismatch to the order of the Frank–Wolfe and cutoff exits. A rounded shape can reach an existing support with a gap on either side of zero. On the same tilted fixture, moving sphere and capsule positions by one representable FP32 interval changed contact identities in up to 14 of 128 worlds in MuJoCo Warp itself. Track active rows and resulting motion alongside raw contact identities in the cross-backend comparison.

The convex model binds a single `uint4` array for each batch. Record 0 holds the EPA vertex, face and horizon capacities in Y, Z and W. Record 1 holds the distance tolerance as float bits, the GJK and EPA iteration limits, and the maximum polygon vertex count. Record 2 holds the four section offsets measured in `uint4` records. The sections are the float-bit vertex and normal records, packed scalar adjacency, topology records, and packed scalar polygon and incidence links. The topology section starts with one descriptor per geometry. A mesh descriptor points at its face records and vertex-incidence records within that section. Face records hold the vertex link offset, vertex count and normal index. Vertex-incidence records hold the face link offset and incidence count. Scalar offsets within adjacency and link sections are measured in 32-bit words.

The native collision cooker packs closed hull faces, support adjacency, and heightfield grids into this layout. Geometries that share a hull reuse its topology and vertices. Heightfields sharing a sample grid reuse its elevations and retain their own physical scale. Model shape types select the native compute passes. Worker scratch is shared across worlds and reused by the convex and heightfield passes in order.

Clear convex status once per step. Schedule `collide_convex` after primitive contact production and before row assembly. Convex and heightfield workers stride over the shared candidate stream. Each worker reuses its scratch across worlds, deriving the geometry and contact ranges from the candidate's world ID. Allocate `2 × vertex capacity + face capacity + 5 × maximum polygon vertex count` `uint4` records and `horizon capacity` `uint` records per worker. The compute submission declares those ranges as scratch writes and the shared contact stream and status as read-write outputs. The packaged convex stage uses 12 storage bindings, including the common narrowphase inputs and outputs.

## Resident ray queries

`BuildPhysicsRayIndex` cooks one shared scene topology with the engine's SAH builder. Pass the finite AABBs and their scene geometry IDs, and list planes separately. Record 0 indexes the node links, packed primitive and plane lists and plane count. Record 1 holds the scene node count, refit batch offset, number of subtree batches and whether a root batch follows. Internal links identify both children and the next node after the subtree. Leaves identify their range in the packed geometry IDs. The node count terminates traversal.

`refit_ray_bvh` consumes `sap_project` bounds from the same world snapshot as the ray geometry frames. Allocate two `float4` bounds per node per world, and share the immutable index. Run one group per subtree on X and world on Y, then a group per world for the root batch if present. Each group processes its nodes from leaves toward the root. Declare the subtree batch as a write, the root batch as read-write, and the query as read-only. For reusable RHI work, record complete-write ranges for the projected bounds and ray hits. A single subtree also writes the entire scene BVH bounds range. For a split tree, initialize that allocation once during preparation since the root batch reads a binding spanning the whole allocation. Reuse the completed bounds for all rays on that snapshot.

`raycast_worlds` traces one ray per invocation, using groups of 64 on X and worlds on Y. Ray inputs are shared when the settings select one input row or supplied per world. Each ray specifies its origin, maximum distance, unit direction, layer mask, optionally excluded body and whether to include static shapes. Equal distances select the lower geometry index. `AppendPhysicsRayMesh` cooks each mesh's original triangles into a shared local tree and returns its offset for the geometry metadata. Heightfields share collision samples and use their clipped subgrid and exposed sides. Results stay in the device buffer with distance, normal, geometry and body IDs. A miss writes distance `-1` and invalid IDs.

The device scene query packs caller-owned origin and direction ranges on the GPU. It can write point, normal, distance and hit flag ranges in the same submission. Input ranges can share storage with the outputs because the pack finishes before projection. A projected miss writes a zero point and normal, positive infinite distance and a zero hit flag.

The ordinary closest-hit scene APIs use this query plan for both host and device callers. The plan reuses immutable geometry from the accepted scene layout and reads the current published pose buffer directly. Results name the same accepted world and fixed step as the pose source.

## Contact constraints

The contact row entries reserve contiguous CSR rows for each contact. They walk the two DOF chains, omitting shared ancestors, then project the contact frame onto the point and angular Jacobians. The continuous-time row update computes the reference acceleration and regularization from the projected velocity, material and world timestep. The setup entries select the initial acceleration, evaluate the constraint residual, and compute the force, cost and state for the chosen friction cone.

The per-world row and nonzero counts retain overflow. Skip any incomplete matrix and report the exceeded capacity before publishing or integrating the step. Contacts, equality, limits and friction loss share the row stream and the CG and Newton solvers. Equality is bilateral, limits are unilateral, and friction loss caps the force on either side of its quadratic region. The objective, line search and Newton curvature use those same laws. Flex rows and the discrete integrator require additional producers.

Prepare the symmetric mass adjacency once per model. Store `nv + 1` CSR offsets followed by pairs of a column DOF and its packed mass index, with the diagonal first in every row. CG reads the iteration and line search limits and packed matrix size from `cgOptions`. The world records in the constraint settings supply the convergence and line search tolerances in their last two words.

Initialize the solver after the row assembly, mass factorization and warm-start selection. Clear and compute `Jᵀf` in a workgroup per world, form the gradient, apply the existing mass solve as the preconditioner, and update the Polak–Ribière direction. The mass search product and smooth directional derivative share one dispatch. Compute the Jacobian search product before the bracketed Newton line search. The accepted step updates acceleration, its mass product and the constraint residual. Re-evaluate the objective at that residual before forming the next gradient. A final gradient and direction check distinguishes convergence from hitting the budget. Use a final projection for publication, including zero force for worlds without constraints. Worlds track status and line search exhaustion on-device. The bounded sequence can be recorded in one compute packet, with no intermediate host readback.

## Joint and spatial constraint assembly

The scalar model stores one record per limited joint, DOF with friction loss, or authored scalar equality. An equality names its first joint, an optional second joint and the coefficients of a quartic coupling in the second joint's displacement from reference. A single-joint equality uses its constant term. The activation matrix is per world and indexed by authored equality id. Limit rows use the signed distance to the nearest scalar bound or to the ball joint's maximum rotation angle. All rows store the original source id and their Jacobian in the common sparse layout.

The spatial model packs one nine-record descriptor per connect or weld, followed by its sparse supports. An endpoint gives the authored body and local frame, its welded body and tree root. Resolve sites to local frames when building the model. A support record carries a DOF, the bit mask of endpoints whose chains contain it, and the owning body for quaternion DOF derivatives. Build and sort the union of the two chains once. Common ancestors can contribute at both anchors even when their angular contributions cancel. Connect writes three translational rows. Weld adds three orientation rows and the corresponding velocity-dependent acceleration shift. Each dispatch uses twelve storage bindings.

Use one row-counter reset for all producers. Assemble spatial equality after current position kinematics and before overwriting the stored body velocities and DOF derivatives with the velocity phase, matching the reference fixed-step order. Initialise those stored values with the world's initial state and retain them between steps. The current generalized velocities still supply `J*qvel`. Assemble smooth forces and factor mass before starting the solve. Both row producers consume the same per-world fixed timestep and are independent of host-frame timing.

## Newton constraint direction

Build the symbolic pattern once from the mass and contact supports for the step. A world with `t = ceil(nv / 8)` uses `t * ceil(t / 32) + 5 * t + 3` words. These hold the tile bitset, numeric tile offsets, component offsets and members, temporary roots and cursors, and the factorization error flag. Reverse elimination adds fill and counts packed upper tiles. The fourth word of the solver options is the numeric tile capacity per world. Each packed tile has 64 floats. A second option record supplies the number of X workgroups for contact assembly, which loops over rows at that stride.

After each gradient update, run `initialize_newton_matrix` with one workgroup per tile column on X. Each group clears its packed slice and seeds the upper triangular mass entries through the symmetric adjacency. Then `add_newton_contacts` evaluates each row's curvature in workgroup memory and accumulates its tile entries. The elliptic middle region uses the local cone curvature. Symbolic elimination assigns tiles to independent components. Dispatch `solve_newton_components` with `t` groups along X. Each nonempty group processes one component, preserving descending DOF order for Cholesky, and solves its direction from the factor within the same group. One finalization group per world checks whether any component failed, combines the direction norms, and determines convergence. The direction uses the shared search products, line search, and accepted-step update. Capacity exhaustion and an invalid diagonal are reported separately before publishing a step.

## Rigid tree activity and sleep

Cook the contiguous body, DOF and joint ranges for each movable tree. The first topology record holds the tree, body, DOF and joint counts. The second points to the tree, body and DOF tables and gives the number of dependency edges. Use two records per tree, one for the body and DOF ranges and one for the joint range and sleep eligibility. Map each body to its tree or `NoIndex` for a fixed body. Map each DOF to its tree and velocity scale. The per-world sleep settings hold the required consecutive quiet steps and the velocity tolerance as float bits. Persistent state keeps the quiet age and a sleeping group root or `NoIndex` when awake.

Once contact and constraint records are available, initialize both union forests. Restore the previous sleeping groups into the wake forest. A physical contact connects movable neighbors for waking. A moving fixed or kinematic endpoint wakes its movable neighbor. Sensor-only contacts leave the wake graph alone. Constraint rows connect their supported trees in both forests. Additional dependency edges can opt into waking and also into remaining in the same sleep island, using per-world activity flags. A sleeping tree checks for changed pose, applied force, wrench or explicitly injected velocity. Propagate the youngest wake age across the completed wake forest.

Reset the DOF, joint and world counters once before publishing awake work. Each active tree reserves its DOF and joint ranges and writes pairs of coordinate and world indices. The first active root to claim a world appends its original world index once. Integration reads the coordinate lists with GPU-generated indirect counts. Advance the clock on every fixed step.

For the constraint solve, generate indirect arguments using the original per-world X and Z work sizes and the compact world count for Y. Compile the solver entries with `INX_AWAKE_SOLVER_WORLDS=1` and bind the world list at slot 31. The seed, residual and objective entries, CG and Newton stages, and optional mass preconditioner resolve their Y index through that list. All simulation buffers keep their original world indices. Clear the force and solver progress of inactive worlds before the compact solve. Contact generation and the graph inputs retain their original layout. In the standalone recipe, pose prediction, collision and the smooth solve run before compaction, and the optional discrete free-body correction still uses the original world grid. A partially awake world retains its full constraint layout.

After integration, measure weighted velocity and external activity. Reduce the minimum quiet age across each current constraint island. Put a tree to sleep when its entire island has been quiet for the required number of steps. Record the shared root and zero velocity and acceleration. The next step that remains asleep clears the prior warm start. This sequence runs at the fixed-step boundary on the GPU.

## Fixed-step state publication

`InxPhyGpuStep` binds the cooked programs to a native `ComputeWorkRecipe`. It uploads the shared model, clears reusable constraint scratch on the device, and keeps the world data resident. With a collision model and solver settings, it connects primitive, convex, and heightfield contacts to sparse elliptic constraints, the CG solve, and Euler integration. Device candidate counts drive the narrowphase passes. Each substep initializes its solver grids and counts the worlds with live constraints. As worlds leave CG, the last one clears the variable-size indirect grids for that substep. The direction dispatch uses its own launch arguments and checks each world's status. This keeps completion and publication in the same command sequence without a host observation. Ordinary scene ownership remains to be connected.

Initialization computes the translational inverse weight from the reference pose once per shared model. It reuses position and inertia passes for a single world row, factors the reference mass in packed ancestor order, and forms the inverse entries on each ancestor chain. Projecting these entries through the translational Jacobian at a body's center of mass gives the mean diagonal used by contact regularization. The factor and inverse scratch retire with initialization. This follows the reference projection in [MuJoCo's model constant setup](https://github.com/google-deepmind/mujoco/blob/3.4.0/src/engine/engine_setconst.c#L323-L351).

For a host consumer, run `snapshot_generalized_state` or `snapshot_contact_state` after the last step writes. Dispatch X over the larger of the position and velocity widths, with at least one group, and Y over the worlds. Bind the complete clock span for the exact batch. The snapshot stores `worlds × nq` position scalars, then `worlds × nv` velocity scalars, then one clock per world. `snapshot_contact_state` appends one unsigned status word per world. A nonzero status prevents position, velocity, warm start, and clock advancement. Bits 0 through 4 mark batch candidate capacity, world contact capacity, constraint capacity, invalid solver state, and narrowphase workspace capacity. Each section preserves world order.

Reuse the snapshot allocation with the recipe and declare it a complete write. Request one tail read of the snapshot when preparing the same submission. Its completion ticket identifies the fixed step whose bytes the host receives. Subsequent steps can reuse the device allocation after the copy is ordered, while the accepted read retains its staging contents until consumption. A GPU-only consumer reads the individual resident state buffers.

## Shader compilation

The engine shader cooker builds the `inxphygpu` program archive for SPIR-V or WGSL. The archive retains each entry's storage bindings and workgroup dimensions. The actuation program includes the body and site transmission entries. The constraint, CG, Newton, and mass-solve programs also have variants that resolve the compact active-world indices. Native runtime builds link the SPIR-V archive, and `LoadInxPhyGpuProgram` retrieves a program for the selected device target. The Web player still needs runtime integration. Its current device request caps storage buffers per shader stage at 12, and `evaluate_discrete_actuators` uses 13.
